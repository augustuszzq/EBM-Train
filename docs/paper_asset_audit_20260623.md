# Paper Asset Audit: Current CIFAR Evidence vs Final Paper Claims

Audit date: 2026-06-23

GitHub checkout audited: `661bd16 Add CelebA-HQ256 external validation utilities`

Scope: current CIFAR paper assets only. External validation, ImageNet-32, DRL-style backbone, long-K scaling, batch scaling, and multinode scaling are intentionally excluded from the claim sufficiency decision here unless explicitly marked as non-final placeholders.

## Technical Summary

The current GitHub assets support a narrow CIFAR-10 regime claim, but they do not yet support a broad method-generalization claim.

The safest claim boundary is:

> In the evaluated CIFAR-10, K=100, staged negative-phase EBM regime, using intermediate-stage negative energies in the loss improves training behavior and survives key controls against shallow-chain and pipeline-schedule-only explanations.

The current evidence should not be presented as:

> A broadly validated EBM training method across datasets, model families, and sampler budgets.

The main blocker is not experiment count. The main blocker is presentation and canonical aggregation:

1. GitHub has 62 current-CIFAR logical runs and complete 5k-spaced FID trajectories for all 62.
2. The PDF currently appears thin because it shows too little seed-level and trajectory evidence.
3. There is a real aggregation ambiguity for `pipe_P4_equal` at 500k: one CSV splits the same family into `pipeline` and `strict_pipeline` regimes, while the PDF number appears to use the family-combined value.
4. Before paper freeze, all tables and plots should be regenerated from one canonical source using family-level grouping.

## Canonical Aggregation Problem

The current PDF-style number for `pipe_P4_equal` at 500k appears to be:

| Family | Runs | Best FID mean | Final FID mean |
| --- | ---: | ---: | ---: |
| `pipe_P4_equal`, family-combined | 5 | 49.070 | 59.072 |

This value is reproducible from `training_time_by_run.csv`.

However, `training_time_regime_summary.csv` splits this same family into two rows:

| Regime | Runs | Best FID mean | Final FID mean |
| --- | ---: | ---: | ---: |
| `strict_pipeline` | 3 | 48.378 | 60.969 |
| `pipeline` | 2 | 50.109 | 56.225 |

This is not necessarily a scientific contradiction. It is a naming and aggregation problem. For paper tables, `pipe_P4_equal` should be treated as one canonical family if the implementation semantics are the same. If `pipeline` and `strict_pipeline` are meaningfully different code paths, the paper must not merge them silently.

Required action before PDF freeze:

1. Freeze one canonical grouping rule.
2. Prefer grouping by `family_id` for main paper quality tables.
3. Use `regime` only for timing or implementation taxonomy after normalizing equivalent pipeline names.
4. Regenerate all paper tables and figures from the same collector output.

## Claim Sufficiency

| Claim | Status | Reason |
| --- | --- | --- |
| Intermediate-state negative loss improves CIFAR K=100 training behavior | Supported with caveats | 500k family-level results favor `pipe_P4_equal`; trajectory coverage is complete; seed-level variance must be shown. |
| The effect is not image-space averaging | Supported by method semantics, not by numeric table | Need keep formula and implementation notes explicit. |
| The effect is not a shallow-chain shortcut | Directionally strong | O5 K=25/K=50 terminal controls collapse, but low seed counts require cautious language. |
| The effect is not pipeline schedule alone | Supported | `pipe_P4_equal` vs `pipe_P4_deepest` is the key ablation and should be presented separately. |
| Single-GPU objective effect exists | Supported but secondary | `single_P2_equal` improves over `single_P1_terminal`, but effect size is smaller than pipeline-side result. |
| Wall-clock/system speedup as a headline contribution | Not ready as headline | Timing data exists, but systems claim needs careful wall-clock/GPU-hour/time-to-target presentation and should remain secondary. |
| Broad method generality across datasets/backbones | Not supported by current CIFAR assets | External validation is out of scope here and not ready to mix into the CIFAR O1-O5 ledger. |

## Recommended Paper Presentation Fixes

Minimum no-new-training fixes:

1. Add `Runs` and `mean +/- std` to all main result tables.
2. Add seed-level dot plots or thin-line trajectories.
3. Add a main FID-vs-step figure using `fid_vs_step_with_wallclock.csv`.
4. Split deepest-only into its own mechanism ablation figure.
5. Keep shallow-chain controls as a separate control figure or table.
6. Add one small qualitative sample grid if sample dumps are available.
7. State that wall-clock and GPU-hour evidence is secondary accounting unless the systems section is expanded.

Recommended Results structure:

1. Main Result: staged intermediate-state training improves CIFAR FID.
2. Mechanism Ablation: intermediate energies matter beyond pipeline schedule.
3. Control: the effect is not a shallow-sampler shortcut.
4. Attribution: the loss also changes single-GPU training.
5. Cost Accounting: wall-clock and GPU-hour reporting, not abstract headline.

## Final Recommendation

The user's high-level judgment is correct:

- The bottom-level current-CIFAR data is close to enough for a narrow AAAI-style regime claim.
- The current PDF presentation will look under-supported unless it shows seed variance, trajectory evidence, and the deepest-only / shallow-chain controls more explicitly.
- The paper should not claim broad general method validity until at least one additional axis is ready, such as K-scaling or a second dataset.
- Before any new experiments are prioritized, the paper should first freeze a canonical result source and regenerate tables/figures from it.
